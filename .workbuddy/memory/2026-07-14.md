## 配置 hitl 超时（根因与方案）
- 两层超时：server 端 `sendAndWait` 由 session.ts 的 setTimeout 阻塞等待，上限 `cfg.defaultTimeout`（config.ts 默认 7200s=2h；index.ts:60 的 `--timeout <秒>` 可改）；WorkBuddy 客户端对 MCP tool call 有 request timeout（几十秒），先到则抛 -32001。
- 之前 -32001 是客户端先掐（几十秒 << 2h）。
- 方案：① mcp.json 的 hitl 块加 `"timeout": <毫秒>`（客户端上限）② args 加 `"--timeout","300"`（server 等待上限 5min）。约束：客户端(ms) > server(s×1000)。
- 单位歧义：WorkBuddy `timeout` 字段单位文档不一致（多数毫秒 60000=60s，个别帖子用秒）。按毫秒配 360000(6min)。
- bug：index.ts:60 注释"默认 1200"与实际 createConfig 默认 7200 不符。
- 已写入 mcp.json：hitl 块 args 加 `--timeout 300`，顶层加 `"timeout": 360000`。
- 改配置后 mcp__hitl__* 工具从索引消失（ToolSearch 精确匹配返回无关工具）→ 需在 WorkBuddy MCP 面板手动重载/重启 hitl 进程后才生效并重新注册。重载不能由 agent 触发，是宿主端动作。
